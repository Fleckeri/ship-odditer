# CLAUDE.md: Ship Odditer

Context for anyone (human or Claude) continuing development. Read this before changing anything.

## What it is

**Ship Odditer** ("Egg Inc. Mission Drop Calculator") is a single-page web app. For any Egg, Inc. spaceship,
mission length (Short / Standard / Extended), target, and star level, it shows the chance of getting each
artifact, stone, and ingredient from one mission, by rarity, plus a mission reward simulator. All maths runs in
the browser from pre-built data files. Version 1.2.0 (Nov 2026); see `CHANGELOG.md`.

It ships one way: an **installable, offline-capable PWA** at <https://fleckeri.github.io/ship-odditer/>, built and
deployed by GitHub Actions (`.github/workflows/deploy.yml`; Pages source "GitHub Actions"). The workflow fetches
the latest upstream drop data, builds `docs/`, runs the smoke test, and deploys: on every push to `main`, daily,
and on demand. Generated files (`app/data.json`, `app/targeted/`, `docs/`) are not tracked by git.

It used to also run as a Claude.ai artifact; the owner retired that in Nov 2026. Don't republish it, and don't
add artifact-specific code back.

## Repository layout

```text
app/ship-odditer.html   The page body: CSS + HTML + JS in one file, without <!doctype>/<html>/<head>/<body>;
                        build_pwa.py wraps it. The only source file for the UI.
app/data.json           Generated by tools/build_data.py (not tracked). Readable: indented, one drop row per line.
app/targeted/<ship>.json Targeted drop counts per FTL ship, generated (not tracked) and readable; loaded on demand.
app/icons/*.webp        Item icons (64 px) and ship icons (128 px), copied by tools/copy_icons.py.
app/app-icons/*.png     App/PWA icons, generated by tools/make_icons.py.
app/fonts/              Self-hosted Chakra Petch and Atkinson Hyperlegible (woff2, Latin + Latin Extended) and
                        their SIL OFL licences, plus odditer-symbols-400/700.woff2 (★ → ≥ ≈ ᴇ, our own; see below).
docs/                   Built site (generated, not tracked; the workflow deploys it). JSON is minified here.
tools/                  Build scripts; tools/update_data.sh runs the whole pipeline (see "Build pipeline").
.github/workflows/      deploy.yml: fetch data, build, test, deploy to GitHub Pages. release.yml: GitHub release per tag.
tests/                  Playwright smoke test, slider benchmark, tiny static server (Node).
vendor/                 Local clones of upstream repos (git-ignored): vendor/egg, vendor/eggincassets.
```

Readable JSON in `app/` costs nothing at runtime: `build_pwa.py` minifies it into `docs/`. Fully indented and
served, it would be ~3× bigger, ~27% more to download, and slower to parse.

## Build pipeline

Needs Python 3.10+ with Pillow and NumPy (SciPy only for `fit_egg.py`), and Node 18+: `npm ci` installs esbuild
(the build minifies the page's CSS and script with it) and Playwright for tests.

```bash
tools/update_data.sh            # fetch upstream (sparse, blobless clones in vendor/), build data, icons, and docs/
python3 tools/build_pwa.py      # rebuild docs/ only, after editing the page
npm run dev                     # serve docs/ at localhost:8017, rebuild on save, reload open tabs (no service worker)
node tests/smoke.js             # must print "all checks passed"
node tests/bench.js top         # slider frame times; compare before/after changes to update paths
python3 tools/make_icons.py     # only to regenerate app/app-icons/*.png (style "bands" is the chosen design)
python3 tools/make_symbols_font.py  # only to regenerate app/fonts/odditer-symbols-*.woff2 (needs fontTools, brotli)
```

**Dev server** (`tools/dev.js`, no dependencies). Polls `app/ship-odditer.html`, `app/data.json`, and
`tools/build_pwa.py`, reruns `build_pwa.py` on a change, and tells open tabs to reload over an EventSource
(`/__dev/events`; the script is injected into `index.html`, allowed by the CSP as same-origin). It serves a stand-in
`/sw.js` that clears the caches and unregisters itself, and sends everything `no-store`, so one reload always shows
the latest build. Starting it again stops the running one (`/__dev/stop`) and takes the port. Use the smoke test,
not the dev server, to check service-worker behaviour. In Claude Code's sandbox it needs
`sandbox.network.allowLocalBinding` (set in `.claude/settings.local.json`), and you start it as `node tools/dev.js`
(npm itself exits 255 there).

`update_data.sh` clones or fast-forwards `vendor/egg` (data folders only) and `vendor/eggincassets` (64 and 128 px
icons only), sets `DATA_DATE` to upstream's commit date and `UPSTREAM_COMMIT` to its commit, then runs
`build_data.py`, `copy_icons.py`, and `build_pwa.py` (about 10 s). The footer's "Data updated" date is filled from
`data.json` at runtime, and the footer's version from `package.json` at build time; nothing to edit by hand.
`EGG_REPO=/path/to/egg` points `build_data.py` at another clone.

**Deploy workflow.** Upstream (carpetsage/egg) commits fresh drop data once a day, so the workflow also runs daily
(07:17 UTC). `docs/version.json` records the app version, build hash, data date, repo commit, and upstream commit;
a scheduled run that finds the live site already matching both the current commit and upstream's latest skips
the build. The smoke test gates every deploy, so bad upstream data can't break the live site. The runner is pinned
(`ubuntu-24.04`) so a new `ubuntu-latest` can't break Playwright's browser setup; action versions are the latest
majors as of Nov 2026 (checkout v7, setup-node v7, upload-pages-artifact v5, deploy-pages v5). A `keepalive` job
re-enables the workflow through the API on every scheduled run (`actions: write`, no commits), because GitHub
turns off schedules in public repos after 60 days without repository activity and data refreshes make no commits. Data isn't
committed because it changes daily (~8 MB of generated JSON per refresh would bloat the repo); upstream's history keeps every
snapshot.

**Releasing.** Bump `version` in `package.json` (and `package-lock.json`), add a `CHANGELOG.md` entry headed
`## X.Y.Z (date)`, commit, tag `vX.Y.Z`, push (`git push origin main vX.Y.Z`). The footer shows the new version after
the deploy. Pushing the tag runs `release.yml`, which creates the GitHub release "Ship Odditer X.Y.Z" with that
changelog section as its notes (it fails if the section is missing, skips a tag that already has a release, and marks
it latest only if it's the highest version). For a tag pushed without a release, run it from the Actions tab with the
tag name. Commits and tags are GPG-signed (`commit.gpgsign`), so they're made from the owner's own terminal. Don't `git grep` across the blobless
`vendor/egg` clone (it downloads every blob); use `git show HEAD:<path>`.

`build_pwa.py` writes `index.html` (skeleton, meta, link-preview and SEO tags, CSP, service-worker registration),
`manifest.webmanifest`, `sw.js`, `sitemap.xml`, minified data, icons, fonts, and `.nojekyll`. The page's CSS and
script are minified with esbuild (top-level names kept, so tests can reach `state`, `render()` and the rest); the
smoke test and pixel-identical screenshots confirmed the output matches the unminified page (Nov 2026).

## Data sources (and what each field means)

All from **carpetsage/egg** (<https://github.com/carpetsage/egg>, MIT, fork of fanaticscripter/egg by @mk2):

- `wasmegg/artifact-explorer/data/loot.json`: player-submitted drop counts from **Menno's drop data tool**
  (players opt in via the wasmegg-carpet Rockets Tracker). Per mission → level → target → items with
  `counts[4]` (common, rare, epic, legendary) and `totalDrops`. Untargeted is `targetAfxId === 10000`
  (`ei.ArtifactSpec.Name.UNKNOWN`). Other target ids are afx ids: one per artifact/ingredient family, one per
  stone (tiers 2-4), one per stone fragment (tier 1, ids 2 and 44-52).
- `wasmegg/_common/eiafx/eiafx-config.json`: mission parameters per ship and duration (`seconds`, `capacity`,
  `levelCapacityBump`, `minQuality`, `maxQuality`, `levelQualityBump`) and `levelMissionRequirements`
  (per-star launch-point increments).
- `wasmegg/_common/eiafx/eiafx-data.json`: item names, tiers, families, icons, qualities, per-rarity effects, slots.

Icons: **carpetsage/eggincassets** (game art © Auxbrain). Theme and UI glyphs: **Lucide** (ISC). Fonts: SIL OFL.
`LICENSE` is the plain MIT text (so GitHub detects it); third-party terms live in `THIRD_PARTY_NOTICES.md`.
The owner said **don't use wasmegg.netlify.app** (stale); use **wasmegg-carpet.netlify.app**.

**Targeting facts (checked Nov 2026).**

- Only FTL ships (Quintillion Chicken and up) can target. Upstream has one global valid-target list with no
  per-ship limits, and the data agrees. Pre-FTL ships log a few hundred stray targeted drops; we drop them.
- **Stone fragments are hidden** (`OFFERED_KINDS` in `build_data.py`; the wasmegg explorer does the same with
  `noFragTargets`). The game allows them, but the owner chose to hide them because targeting them is almost never
  worthwhile. The Target list ends with a note saying so; its tooltip and Nerd Stuff say it too.
- **No published targeting formula.** The wiki only says it raises the family's rate and lowers quality. The boost
  varies ~1.5-8× by target even on one mission, so the app uses each target's measured shares, never a multiplier.

`data.json` shape:

```text
dataUpdated: "YYYY-MM-DD"
items: { <itemId>: { n: name, f: family, t: tier 1-4, c: "art"|"stone"|"ing", i: icon file, q: quality,
                     e: [[rarity 0-3, effect text, slots|null]...], fe: family effect } }
ships: [ { id, name, icon, ftl: bool, maxStars, req: [per-star launch-point increments],
           missions: [ { id, label: "Short"|"Standard"|"Extended", seconds, cap, capBump, qMin, qMax, qBump,
                         levels: { "<star>": { n: totalDrops, d: { <itemId>: [count common, rare, epic, legendary] },
                                               tn: { <afxId>: targeted totalDrops } } } } ] } ]
targets: { <afxId>: { n: name, k: "art"|"stone"|"ing", i: itemId whose icon to show,
                       it: { "<tier>": itemId } (every tier with this afx id, even ones that never drop) } }
```

`targeted/<ship>.json` is `{ "<mission index 0-2>": { "<star>": { "<afxId>": { n, d } } } }`, the same `{n, d}`
shape as an untargeted level. `d` values are how many of each rarity were logged at that level, with trailing
zero rarities left out (`[12, 3]` = 12 common, 3 rare): exact, and much smaller than shares (about 30% less to
download). `seen()` reads them; `share()` divides by `n`. `build_data.py` fails if item text contains `< > & "` (it's written into the page as HTML).

## Formulas (verified against carpetsage/egg `lib/missions.ts` on 31 Oct 2026)

- **Capacity** = `floor((capacity + levelCapacityBump × stars) × (1 + 0.05 × ZeroG) × event)`, ZeroG 0-10
  (`boostedCapacity`); `event` is the capacity event toggle's 1, 2, or 3 (`state.dcap`, in `capMult()`). Upstream tools don't model
  capacity events, so rounding once at the end is our assumption (the game may differ by one item). Every
  `mission-capacity` event in `periodicals/data/events.json` is ×2 but one (×3).
- **Duration** = `seconds × (1 − 0.01 × FTL)`, FTL 0-60, only for ships ≥ Quintillion Chicken (`isFTL`).
- **Quality range** shown as `minQuality – (maxQuality + levelQualityBump × stars)`, matching the mission-list tool.
- **Star thresholds** are cumulative sums of `levelMissionRequirements`. **Launch points**: 1 / 1.4 / 1.8 per
  short / standard / extended. "From scratch" runs = `ceil(cumulative / pts)`; "From N★" = `ceil(req[N] / pts)`
  (the mission-list tool's `launchesToStar`).
- **Days** use rounds of three launches: `ceil(launches / 3) × duration` (like `timeToStar`).
- **Expected copies per launch** `lam = share × capacity`, `share = count / n` (the rate the explorer shows).
- **Per-launch chance** uses the exact fixed-capacity model: a launch draws `capacity` items independently, so
  `P(≥1) = 1 − (1 − share)^capacity`, implemented as `lamEff = −capacity · ln(1 − share)`, `P = 1 − e^(−lamEff)`.
  The explorer's optimizer uses the Poisson shortcut `1 − e^(−lam)`; they differ a lot for tiny early ships
  (Chicken One: 91.0% vs exact 95.4%), so keep `lamEff`.
- **Launches for the target odds q**: `kAt = −ln(1 − q) / lamEff`.
- **"All in one launch"** = product of per-item P. **"At N% odds: all in k launches"** = smallest k with
  `Π(1 − e^(−k·lamEff_i)) ≥ q` (binary search). Both treat items as independent, which is slightly optimistic.
  **"… target in k"** is the same for the target's item in that tier.
- **Rough values**: cells resting on < 5 sightings (`seen() < ROUGH`) get class `rough` (faded, dotted underline)
  and "≈" before the number in tooltips. The explorer's optimizer zeroes legendary buckets under 5 observations.
- **Sample size**: `SMALL_SAMPLE` = 200,000 items. Below it the "Warning: Small Sample Size" box shows (and the
  Target list row is yellow); under 20 missions it's "Warning: Very Little Data" (the explorer hides those);
  no data at all is "Warning: No Data" (red in the Target list).

## Page architecture (app/ship-odditer.html)

**State** (`state`): `ship, len (0-2), target ("none"|afxId), star, rar ("all"|0-3), cat ("art"|"stone"|"ing"),
zerog (0-10), dcap (1|2|3, capacity event multiplier; an early save's `true` loads as 2), ftl (0-60), odds (1-99), sort ("tier"|"rarity")`. Saved to `localStorage["mission-odds"]`
(debounced; flushed on `pagehide`) and **validated field by field on load** (old or damaged saves fall back to
defaults). Theme: `localStorage["mission-odds-theme"]`. Dismissed install panel:
`localStorage["mission-odds-install-dismissed"]`. After an update's reload, `sessionStorage["mission-odds-updated"]` briefly holds your place. Keep these key names, or existing users lose their settings.

**Targets.** `state.target` is what the user picked; `curTgt` (set at the top of `render()`) is the target in
effect: null on pre-FTL ships or when the mission has no data for it, so the choice survives switching ships.
`level(s)` returns the targeted `{n, d}` when `curTgt` is set, so every table, strip, odds figure, and the
simulator follow it. `render()` fetches the ship's targets file first if needed (`loadTargets`), falling back
to untargeted on failure.

**Two render paths** (the main performance design):

- `render()`: the **full** rebuild, used by dropdowns, stars, Items, Rarity, and the initial load. It calls
  `renderTop()` (toolbar readouts, mission card, captions), rebuilds `#tiers`, then `flipRows`, `renderReward`,
  `holdView`.
- `renderValues()`: the **light** path for the three sliders, queued with `schedule("values")` (at most once per
  frame). Sliders never change which rows exist, so it patches numbers in place:
  - `patchTiers` → `patchSection` → `valueFor(key)` recomputes each number from its key (`t<tier>|all`,
    `t<tier>|see`, `t<tier>|tgt`, `<item>|per|<r>`, ...).
  - Only on-screen tables update; off-screen ones are marked `_dirty` and caught up by `catchUp` on view.
  - Heat strips redraw at most every `STRIP_MS`. The simulator re-rolls 320 ms after Zero-G settles.
  - Any new feature affected by a slider must work in this path too: add its key to `valueFor`, or rebuild a
    small block with `setHTML`.

**Rolling numbers.** Every animated number is written with `N(key, value, format, note?)`.

- `N` emits `<span class="n" data-k data-v data-f>` plus an optional `<span class="aft">` note ("(13.8 months)").
- `syncRolls(roots, instant)` rolls changed values with a cubic Hermite ease (`ROLL_MS` 900 ms); a value
  retargeted mid-roll keeps its speed. Notes fade out, the number rolls, the new note fades in.
- Width: numbers in table cells reserve nothing (fixed, right-aligned columns). Elsewhere, on a new roll or
  target, the box reserves the wider of the shown and final values, measured with a canvas plus a per-font
  tabular-digit correction (`digitFix`, measured once in the page). So a number moves once, by exactly what it
  needs, and doesn't settle back on landing.
- Only numbers in on-screen blocks roll (`VIS`, IntersectionObserver); the rest snap. Formats live in `FMT` and
  return plain text. Times use the fixed shape `1d 04h 05m`.
- `setHTML(el, builder)` rebuilds a block only if its structure changed; otherwise it hands new values to the
  roller. Keys must be unique on the page.

**Tier tables.** One column plan per view (`colPlan` → `<colgroup>`, `table-layout:fixed`), so every tier's
columns line up and long names wrap. Widths in `COLW` were sized by sweeping every ship/length/star/target/
rarity/odds combination for overflow. They carry ~4 px of headroom over the macOS sweep, because Linux (the CI
runner) and Windows render the same fonts slightly wider; without it, CI caught a 2 px overflow. Launch counts ≥ 1M show as "1.09M"; tiny per-launch values as `2.9ᴇ−3`.
The item column's minimum is CSS (`--name-w`, 170 px; the table gets the other columns' total as `--cols`). At the
compact breakpoint (`max-width:820px` or `max-height:520px`) it shrinks to a 50 px icon column: the name
(`.item-n`) is visually hidden but still read by screen readers and shown in the row tooltip, and the target
crosshair is hidden (the row keeps its green tint and bar). While a table is scrolled sideways (`.scroll.scrolled`, set by a capturing scroll
listener on `#tiers`), a hairline and soft shadow mark the pinned column's edge.

**Pinned column labels.** The scroll box around each table can't stick its header to the page (a sticky element
sticks to its nearest scroll box), so each section has a `.pin` before the table: a zero-height `position: sticky`
strip holding a copy of the label row only (`labels`; not the "Any rarity / Common…" band, whose colours are enough),
`aria-hidden` with its `tabindex`es removed. At rest it sits exactly over the real row (lowered by `--band`, the band
row's height, from `measureBand`); scrolled, it stays under the toolbar (`--pin-top`, the toolbar's height from a
ResizeObserver) and is clipped where the section ends, which is why `.tier` is `overflow: clip`, not `hidden` (a
hidden box is a scroll container and would capture the sticking). Not being a scroll container, `.tier` also
needs `min-width: 0`: as a grid item it would otherwise grow to its table's full width, past the page's margins. The scroll listener copies the table's
`scrollLeft` to it. CSS sticky keeps it smooth on iOS, where moving it from a scroll handler would lag a frame.

**Motion.** `snapRows`/`flipRows` slide table rows (FLIP) and ease section heights (`FLIP_MS` 300);
`snapGrid`/`flipGrid` do the same for reward tiles; `rumble()` shakes Relaunch. View transitions, where supported:
the theme button spreads the new theme in a growing circle from the button (skipped when Auto changes nothing), and
picking a ship while the mission card is on screen flies the old ship off down-right as the new one arrives
(`shipTransition`; the `ship` view-transition name is set only for that transition; the new view is captured once
`render()`, which returns its target-loading promise, and the picture are done). The page itself swaps instantly
(`::view-transition-*(root)` animations are off). Everything respects `prefers-reduced-motion`.

**Links.** A share link carries every setting as a 12-character code, e.g. `#a280a0a1o1e0` (`linkCode`): fixed-width
base-36 fields, in order: ship (its place in `DATA.ships`, the game's own order; `build_data.py`'s `SHIPS` is
append-only for this) 1, length 1, stars 1, target (afx id, `--` for none) 2, items × 5 + rarity (0 all, 1-4) 1, Zero-G 1,
FTL 2, odds 2, (event − 1) × 2 + (sort is rarity) 1. `readLink()` reads them in turn; each valid field applies, and
invalid or missing ones keep the current value, so a shorter code sets only its leading fields: the shortcuts are
`#92` (ship 9, extended), keeping stars, target, and research. `consumeLink()` applies the link on load (before
`wire()`) and on `hashchange` (a shortcut opened while the app runs), saves at once, and clears it from the address
with `history.replaceState`, so the address bar stays clean; reloads and bookmarks open the saved settings. The share
button builds the link on demand (`linkURL()`). The field order is the format: shared links and installed shortcuts
carry it, so add new fields at the end and never reorder. `#sim` (`goView`) scrolls to the simulator once the tables
exist and holds it there with `holdView` while the tier sections above take their real heights (content-visibility).

**Sharing.** The round button on the mission card's top right shares the mission's link: the share sheet where
`canShareSheet()` (Web Share and a coarse pointer), otherwise it copies the link and flashes "Link copied" (desktops
get a link icon). The simulator's button shares the haul as a 1080 px PNG (`drawHaul`: the mission, the tiles in list
order with static glows from `glowSprite`, the app's eggs from the page's `.logo` paths, and the site address), always
in the dark theme's colours; where the share sheet can't take files, or there is none, it's saved ("Save picture").
`haulPicture()` caches the picture per roll (`rewardSerial`) and sort, and drawing starts on `pointerdown`/hover/focus
so the share sheet opens while the tap still counts as user activation (Safari is strict).

**Keep your place.** `pickAnchor` / `holdView` keep the block at the top of the view (a tier section, Nerd Stuff,
or the simulator) fixed for ~1 s after a full render. Skipped while the top of the page is in view; cancelled by
wheel, touch, or paging keys. `html.holding` turns off browser scroll anchoring during the hold.

**Floating Relaunch.** Both buttons share `.fab`. The copy lives in a sticky dock at the end of the simulator
(as tall as the button, so at the section end it sits below the list). When the real button crosses the
toolbar, the copy flies between it and the corner (WAAPI, 420 ms, `fill: forwards`), re-aiming every scroll
frame (`setKeyframes`) so it never flies past the button; `snapHide` hides it instantly after a flight back;
`dock._want` tracks the wanted state. Otherwise, and with reduced motion, it fades.

**Other pieces.**

- `makeDropdown`: accessible custom listbox (native selects can't show icons); rows are flex (icon + `.dd-t`).
  Optional non-option note at the bottom (used for hidden fragments). Icons are preloaded in idle time
  (`preloadIcons`).
- `wireTooltip`: one tooltip for `[data-id]` (items), `[data-tip]` (text: column headers, research labels,
  mission card labels, target badge, Target label) and `[data-tipk]` (computed: the odds column). Wired on the
  tables, simulator, toolbar, and mission card. Hover only for real mice; tap toggles on touch.
- Install panel (`#install`): only where the browser can install (iOS/iPadOS, Safari 17+ on Mac, Android
  browsers, Chrome/Edge/other Chromium desktop) and not already running standalone; opens by itself until
  dismissed. Title names the device; steps use Lucide glyphs in `.ui-key` chips; Chromium's
  `beforeinstallprompt` adds an Install button. The intro link (faded, dotted underline) shows only where install
  is possible and always reopens it; running installed, the intro says "Installed to your device." after a green
  check, centred on the capitals. Browser menu names were written from memory (Nov 2026); check them on real devices.
- Theme: Auto / Light / Dark cycle with Lucide icons and a 2.5 s flash label. Colours are tokens with the
  `prefers-color-scheme` + `[data-theme]` pattern; every colour is defined on `:root` and in both dark blocks.
- `.dots`: a row of values with "·" between those that share a line: each item has a `--dot` (1.3em) gap on its
  left with the dot centred in it, and the first item on each line has its gap clipped away. It does its own
  spacing, so don't add a flex `gap` to the element (`.summary` used to, which doubled the space). Used by the
  tier summaries and the mission card captions.
- **Text sizes.** Every font size is a token on `:root`: `--fs-micro` (.7rem, uppercase labels and column headers;
  the table columns were sized for it), `--fs-small` 13px, `--fs-text` 14px (captions, summaries, warnings,
  notes, tooltips), `--fs-body` 15px (tables, lists, controls), then `--fs-h3/h2/hero/h1`; phones only shrink
  `--fs-h1` and `--fs-hero`. Bold figures inside running text are `--fs-inline` (.9em): at full
  size, bold figures look taller than the grey lowercase around them; words, tags, and a value's note (`.aft`,
  reset to regular weight) keep the text's size. Dotted "explains itself" underlines on the mission card labels
  are a pseudo-element border inset by the letters' side bearings, so they line up with the letters. `text-size-adjust:100%` stops
  iOS inflating some blocks in landscape. Don't add one-off sizes; pick a token.
- **Symbols font.** Atkinson and Chakra Petch have no ★ → ≥ ≈ ᴇ, so each device drew them from a different
  system font. `tools/make_symbols_font.py` draws them on Atkinson's metrics and stroke weights as "Odditer
  Symbols" (two weights, ~0.5 KB each, `unicode-range`d), second in both font stacks. A new symbol the fonts
  lack belongs there too.

## Decisions the owner made (don't undo without asking)

- **Title and logo.** Title "Ship Odditer", subtitle "Egg Inc. Mission Drop Calculator"; page `<title>` "Ship
  Odditer: Egg Inc. Mission Drop Calculator". The app icon (inline SVG, `tools/make_logo_svg.py`) sits left of the title.
- **App icon, design "B / bands".** The game's egg silhouette (fitted from `egg_edible.png`, IoU 0.999, upright,
  width/height 0.742) as nested eggs: blue outside, purple, orange inside. Dark icon on `#0f141b` with dark-theme
  rarity colours; light icon on `#f3f5f8` with light ones. Installed apps use the dark icon; the favicon follows
  the system theme.
- **Intro.** One short paragraph (what it covers, from player-logged missions, adjusts to research, simulates
  rewards). `SHARE_DESC` in `build_pwa.py` (meta, link previews, manifest, structured data) should match it.
- **Colours.** Rarity: common grey, rare blue, epic purple, legendary orange. Target green `--tgt` (= `--ok`)
  `#299b4f` / `#68c77f`: hue 150 at the rarity colours' average OKLCH lightness and chroma. Tier pills in the
  reward list are coloured by the row's rarity, not the tier.
- **Target crosshair** (`TGT_MARK`) marks the target everywhere: after its name in table rows (which also get a
  green tint and bar; not in the icon-only column on small screens), item tooltips, and the Items received list; before **Target** in Nerd Stuff; in the
  dropdown's "None" option; and, with the target's icon inside it, on the hero ship picture's lower left (ship
  art mostly points down-right).
- **Sliders.** Zero-G and FTL purple (epic research). The Odds slider (1-99%, default 50%) is one solid colour that
  shifts blue → purple → orange (oklch mix) with its value.
- **Capacity event toggle.** An unlabelled square button between Target and Zero-G with the game's capacity

## Platform, privacy, and security

- **No third-party requests.** Fonts, data, icons, and scripts are all served from the site, so the app works
  fully offline once installed and no visitor data goes anywhere else. Keep it that way.
- **Content Security Policy** (meta tag; GitHub Pages can't send headers): everything `'self'`, inline scripts
  allowed only by their SHA-256 hashes (computed by `build_pwa.py` on every build), inline style attributes
  allowed, no objects, base URI, or form targets. A feature that needs another origin (e.g. an Egg ID relay)
  must add it to `connect-src` deliberately.
- **Data into HTML.** Item text from upstream goes into `innerHTML`; `build_data.py` refuses text with HTML
  characters. User input never reaches HTML (settings are validated; the target id is checked against the data).
- **Offline and updates.** The service worker precaches every file and serves cache-first, so the app works
  offline. `PRECACHE` maps each file to its hash (first 16 hex digits of SHA-256); the cache name is a hash of
  that map, names included. Each cache also stores the map it was built from (`sw-hashes.json`), so installing a
  version copies files whose hash is unchanged from the old cache without rehashing them (a cache from an older build
  has no map; its files are hashed) and downloads only the rest: a daily data update fetches `sw.js`, `data.json`, and
  `targeted/`, not icons or fonts. An interrupted install keeps what it already checked for the next try; the fetch
  handler reads only its own version's cache, so a half-built newer one is never served. Downloads use `cache: "no-cache"` (the
  server is always asked, so a stale HTTP-cached file can't sneak in, but a file the page just loaded costs a 304
  instead of a second download), and every file must match its hash, so a download that catches a deploy half-way
  fails. A failed install leaves the current version in charge. Each update check costs a ~400-byte 304 for `sw.js`
  (Chrome revalidates with `If-None-Match`; checked Nov 2026). The page registers it with `updateViaCache: "none"` and checks for updates when it returns to the
  foreground and hourly. When a new version takes over (`controllerchange`, not the first install), the page
  reloads into it by itself (`reloadNow`): at once if hidden, otherwise at the first quiet moment (`QUIET_MS`, 2 s
  with no taps, keys, wheel, or scrolling, no dropdown open, no slider held, no tooltip up). It saves where you
  were (`pickAnchor`, else `scrollY`) in `sessionStorage["mission-odds-updated"]`; after the reload
  `restorePlace` scrolls back once the tables exist and shows "Ship Odditer updated · drop data from …"
  (`#update-note`) for 4 s, starting when the page is visible. Until the reload the open page runs its old code but is served the new version's files, so it must not load anything new:
  `loadTargets` reloads into the new version instead (`replaced`; the chosen target survives the reload). It only
  handles same-origin GET requests.
- **Changing a data file's format? Change its path too.** A page that was open when the new version took over may
  still fetch the old path; it should get "not found" (the page falls back to untargeted) rather than misread the
  new format. That's why targeted counts live in `targeted/` and not `targets/`, where earlier builds kept shares.
- **Page skeleton.** `build_pwa.py` adds the doctype, charset, viewport, CSP, and a small reset. To test the raw
  page, put `<!doctype html><meta charset=utf-8><meta name=viewport content="width=device-width,initial-scale=1">`
  in front, or phones emulate at 980 px and text is mojibake.
- **localStorage** is per viewer; wrap every access in try/catch.
- **Accessibility.** axe-core (WCAG 2.1 A/AA + best practice) passes with no ARIA or structure violations
  (Nov 2026). Remaining contrast failures are the owner's rarity colours (rare blue, legendary orange on light
  backgrounds) and grey counts in the reward list headers; changing those needs the owner.
